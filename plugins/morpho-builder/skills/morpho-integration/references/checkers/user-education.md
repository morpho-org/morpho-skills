# User education

Review read-only using [review guidance](../review.md), the [shared manual](../../SKILL.md), [UI principles](../ui-principles.md), the [handbook](../handbook.md) and the applicable product manual. Do not edit or transact. Report concrete defects and evidence limits separately, scoped by product/version; do not infer execution from source or synthetic data.

Check the handbook's [user education](../handbook.md#user-education) guidelines: a visible path to learn more, plain-language explanations and understandable reasons for unavailable actions.

Open every explanatory link and tooltip in the rendered product. A link in source that is clipped, unreachable on narrow layouts or placed only in a footer does not give users a path.

Explanations must agree with the product manual and the [truthful language](../handbook.md#truthful-language) guidelines. A simplified explanation that promises fills, exits, yield or safety is a defect, not a simplification.

Numbers that can worry a user (liquidity limits, liquidation price, fees, penalties, maturity) need an explanation where they appear. Required terms such as LLTV are explained in place; deeper protocol detail can sit behind an advanced reveal.

Unsupported operations should have an understandable reason rather than appearing guaranteed or silently changing meaning.
