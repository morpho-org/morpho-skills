# Information accessibility

Review read-only using [review guidance](../review.md), the [shared manual](../../SKILL.md), [UI principles](../ui-principles.md) and the applicable product manual. Do not edit or transact. Report concrete defects and evidence limits separately, scoped by product/version; do not infer execution from source or synthetic data.

For functionality the integration offers, essential identity, units, source freshness, costs, protection limits and relevant risk information must be available when making the decision, not hidden behind an unrelated path.

Review actual layouts and alternate entry points, including narrow viewports, deep links, loading and errors. Data present in a response or source file does not establish that the user can read or act on it.

Separate absent information from unknown information. Expose actionable failure/restart context without promising capacity or safety that has not been verified.

Keep accrued rewards and historical information independent of active-position visibility. Unsupported operations should have an understandable reason rather than appearing guaranteed or silently changing meaning.

Monitoring notifications, if offered, must identify the affected position and a relevant management destination; a link alone is not evidence of backend delivery.
