# GraphQL-to-REST route map

Apply [SKILL.md](../SKILL.md). These mappings follow the [migration guide](https://docs.morpho.org/developers/api/migrate-from-graphql/) and the linked route references, checked against downloaded OpenAPI GET operations and live public GETs. Each row is one concrete route; combine rows according to **consumed fields**, not query name alone. All successful data is under `data`; lists have an independent top-level `cursor`. Path placeholders are parameters, not literal URLs to request.

## APY history: range versus averaging window

The vault V1/V2 and Blue APY history routes above use these ranges. The average endpoints in SKILL.md use a **different** window-selection contract. These values are not automatically valid for balance/position history.

| `lookback` | Chart range | Sampling | Each point's trailing APY window |
| --- | --- | --- | --- |
| `six_hours` | Last 6h | Hourly | 6h |
| `one_day` | Last day | Hourly | 1d |
| `seven_days` | Last 7d | Hourly | 1d |
| `thirty_days` (default) | Last 30d | Daily | 7d |
| `ninety_days` | Last 90d | Daily | 30d |
| `one_year` | Last year | Weekly | 30d |
| `inception` | Available history | API-selected hourly/daily/monthly by age | 30d |

All exclude rewards. Respect returned timestamps, gaps and early/near-empty-window omissions; do not assume evenly spaced complete data. `seven_days` cannot replace a weekly **averaging window**; `ninety_days`/`inception` cannot replace quarterly/all-time averages. Custom `startTimestamp`, `endTimestamp`, `interval` and `lookbackHours` are not parameters here. UI relabeling is part of migration, not optional cleanup.

For Midnight, with WAD book price `p`, fixed APR = `(1e18 / p − 1) × 31,536,000 / seconds_to_maturity` only for positive remaining time. This is a quote-derived simple APR, not a realized APY window or a guarantee of fee-free execution. Borrow takes bids; an early secondary repay uses asks. Use the product skill and Actions simulation for actual costs/guards.

## Known gaps and semantic changes

| Legacy need | Available surface / gap | Required migration behavior |
| --- | --- | --- |
| Instant `netApy`, `supplyApy`, `borrowApy` | Only fixed-window realized averages in REST | Relabel and record changed semantics; never claim exact instant-rate parity. |
| Arbitrary/quarterly/all-time APY windows and custom sampling | No equivalent in these history routes | Report a gap; chart-range substitutes require explicit approval and honest window labels. |
| Full GraphQL reward totals / vault allocation-derived incentives | Morpho REST excludes Merkl; direct-campaign recipe is narrower | Keep native vs reward source/scope separate. Net APY is a historical approximation; failures unknown, never native mislabeled net. |
| Historical USD/`historicalPriceUsd` | Token price route is current only | Use an explicitly approved external historical source or report unknown; current price is not historical USD. No historical source is bundled here. |
| Vault `metadata.description` | No REST source | Report gap; do not infer description from name or unrelated registry text. |
| Per-vault curator attribution | Config address → curator registry yields zero/multiple profiles | Preserve registry-match semantics; do not claim identity with GraphQL's attribution list. |
| Global/multi-wallet positions | No one-call global/multi-wallet replacement | Repeat supported per-wallet lists with independent pagination. Unknown discovery coverage stays incomplete, not proof of no position. |
| Complete global user activity | Per-vault/user activities + position discovery are partial | Include `active_only=false`, paginate each discovered vault then merge; deduplicate by `chain_id`, `tx_hash`, `log_index`. Missing pages/undiscovered vaults, market actions/migrations/wrappers remain gaps. Transfers carry shares, not invented asset amounts. |
| Current Blue collateral total | Current state has no total; history has sampled `total_collateral_assets` | Latest sample is an explicitly labeled, lagging fallback only; never silent exact replacement. |
| Allocator capacity including V1 | Blue `reallocatable_liquidity` counts V2 only | Explain possible lower capacity and separate immediate liquidity; not a guaranteed executable sum. |
| V2 forced liquidity / caps | Capacities and active-adapter caps differ in scope | No guaranteed executable force-Max; retain penalties, distinguish designated liquidity market vs rest of adapter, and include unscoped caps without double counting. |
| User PnL | Performance uses `average_cost`, transfers netted into balance, realized+unrealized earnings | Not necessarily old GraphQL accounting or historical USD PnL. Non-annualized `return_on_capital` must stay non-annualized. |
| Blue user liquidation feed | No authoritative Blue event feed in mapped REST reads | Collateral-history drop absent known withdrawal is **possible** liquidation only. Exact event/date/seized/repaid amounts remain an API gap; never assert them from snapshots. |
| Unsupported filter/sort, unindexed resources | Fixed route schemas/catalog coverage | Record missing predicate/resource and exact evidence; no made-up query parameters or all-resources claim. |
| Transaction route/chain unavailable | Read availability ≠ Actions availability | Report unsupported intent and block it; do not fall back to SDK/calldata/bundler. Merkl Distributor claims are a documented separate exception, not an invented Actions route. |
| Design/accounting questions inherited from product skills | Health thresholds/colors/copy, Max buffer, Midnight `cost_basis` semantics, roll/margin, Merkl root cadence/deployment/recipient may be open | Keep open/`UNVERIFIED`. Do not invent API/design values or fail solely for missing unresolved values. |

These are known limits, not an exhaustive absence proof. For a new consumed field, verify the current reference and response before labeling it a gap. Add each affected consumer to [migration-report.md](migration-report.md), with evidence, user impact and an explicit decision. Use [verification.md](verification.md) to distinguish reachability, parity and runtime/visual evidence.
